# Golem design decisions

This document records the extracted system's intentional boundaries. It is not a roadmap for a plugin framework.

1. **Durable authority is a SQLite-backed Go service.** Job and event updates are transactional. The pure-Go SQLite driver keeps deployment simple.
2. **SUPERSEDED: transport is Unix socket or loopback HTTP JSON.** Unix permissions remain the local trust boundary, but the deferral of authenticated network transport is superseded by decision 22.
3. **Assignment is explicit by host.** Capability scheduling is deferred; deterministic ownership makes partition behavior understandable.
4. **Process reality is host-local.** A supervisor maintains a durable worker registry and owns a private tmux server. Already-running workers survive service outages; bounded offline restart applies only to missing workers. In the single-daemon deployment (decision 19), graceful SIGINT/SIGTERM shutdown kills the owned tmux server and all workers because they would otherwise be unreachable orphans; a hard crash may leave them for startup adoption/reconciliation.
5. **Lifecycle is common, evidence is harness-specific.** Jobs share stable states while adapters may attach opaque details, progress, questions, usage, and settlements.
6. **PTY access is direct.** Same-host users receive a tmux socket and target. Remote terminal proxying and authentication are deferred.
7. **Artifacts are logical globally and paths locally.** The service assigns an opaque artifact ID. Workspace selectors resolve to persistent named Git worktrees under configured projects or daemon-managed clones; the supervisor still validates resolved working directories and artifact paths against allowed roots. Portable artifact storage is deferred.
8. **Start failures are bounded and durable.** Transient pre-registration failures use persisted attempts and backoff; permanent configuration or authorization failures settle immediately.
9. **Interactive harnesses use lifecycle side channels.** A TUI owns its pane without a tee wrapper. Hook adapters append durable JSONL events and observation advances a persisted byte cursor. Process death remains the crash boundary.
10. **Minimal argv harnesses remain minimal.** Claude and Codex wrappers provide argv templating, transcript, and exit status only; they do not claim resume, usage, native blocking, or steering semantics.
11. **Steering uses tmux keystrokes.** Multi-line input uses bracketed paste followed by Enter. Steering is also an API interaction surface delivered through the same reconciler keystroke machinery as answers. Cancellation remains process-level.
12. **Blocked questions are explicit adapter actions.** The pi hook registers `agents_block`; an answer is delivered as the next TUI message. This avoids guessing from rendered terminal output.
13. **SUPERSEDED: settlement callbacks are best-effort.** The webhook and atomic worklist drop-box notification path was removed in Phase 3. Durable resumable events (decision 20) are now the only prompt notification mechanism; job polling remains the fallback.
14. **Worker tmux policy is private and complete.** It is supplied at server birth and re-applied after starts and supervisor restarts. Worker panes retain exit status; unrelated human-opened panes do not remain after exit.
15. **Pi is one adapter, not the system architecture.** Its profile, event schema, usage fallback, and tool integration live under `harnesses/pi` and `integrations/pi`.
16. **Pi profiles are isolated per job, including substrate integrations.** The adapter always sets a private `PI_CODING_AGENT_DIR` and writes one explicit, audited extension allowlist. It reads only selected defaults/catalog files from an optional source profile. When Herdr is selected, golemd uses its pinned Herdr binary to install `herdr-agent-state.ts` once into a stable private seed under the Herdr root (an absolute `pi_extension` remains an expert override). Golem copies the source bytes with restrictive permissions into each job profile before writing `settings.json`, then allowlists only that private path alongside Golem hooks/web/Tiamat. Herdr is never a second writer against job profiles. Existing seed bytes remain stable across daemon restarts; replacing them is an explicit rollout action. Tmux selection neither requires nor receives the extension.
17. **SUPERSEDED: provider descriptors are never wire data.** Dispatch names only an advertised harness and model. Providers are operator configuration; golemd resolves the model's provider and reads any credential from its own environment while provisioning the private per-job profile. Secrets never enter jobs, events, or API responses.
18. **Builds remain one Go module and one flake.** The CLI, daemon, and render helper are outputs from the same source and lock files.
19. **Deployment is one standalone daemon per host.** `golemd` composes the durable store, HTTP API, supervisor, and private tmux server in one process. Every accepted job is locally owned; fleet awareness and daemon selection belong to clients, not service-side host assignment. Each daemon advertises operator-enabled harnesses and provisioned projects from validated configuration; model inventory may additionally come only from an explicitly configured harness-specific resolver (decision 24), never from dispatch payloads or probing that enables a harness.
20. **Settlement is structured and events are resumable.** The first terminal observation atomically fixes a job's settlement; later settlement attempts are no-ops. Harness verdict/usage and process exit status are augmented with bounded artifact and resolved-worktree facts. A SQLite-assigned global sequence orders durable `job.created`, `job.state`, `job.progress`, and `job.settled` events. SSE replays strictly after a caller's cursor and then tails live; it replaces callback/drop-box delivery without replacing ordinary job polling.
21. **Remote attach is restricted SSH, with the job selected by username.** An optional embedded gliderlabs SSH listener accepts only operator-authorized public keys; the full job ID or an unambiguous prefix selects a live tmux worker. It accepts PTY/window changes and a shell request solely as the attach trigger, while exec, subsystems/SFTP, forwarding, agent/X11 forwarding, and all other session requests are rejected. Live jobs advertise an SSH `activation` object, while the existing host-local `terminal` object remains the faster same-host path. Attach is writable but does not steer through Golem APIs or mutate lifecycle/settlement state.
22. **Artifacts are retrievable and TCP is bearer-authenticated.** A shared bounded enumerator supplies both settlement and live-job artifact listings (regular files, relative paths, size and modification time, 100-entry cap with an explicit truncation marker). Byte retrieval uses HTTP content serving and ranges. Requested paths reject absolute, dot, dot-dot, empty, and backslash components; symlinks are evaluated and the real target must remain below the real per-job directory, itself below the configured artifact root. Every TCP request, including SSE and health checks, requires a constant-time match against an operator-configured bearer token when tokens exist. Unix sockets are exempt because filesystem permissions remain their trust boundary. Tokenless TCP is allowed only on literal loopback addresses with a warning; non-loopback binds require a token. TLS remains the tailnet or tunnel's responsibility, and artifact storage remains host-local.
23. **The run substrate is a backend, and tmux stays the default.** `backend.Backend` names the operations a job's process reality needs. `backend/herdr` drives protocol 20, but its server is private child infrastructure owned by golemd—not a user/shared session. `[herdr]` starts the child with an explicit session and socket plus isolated HOME/XDG config/state; inherited Herdr selectors are removed. A live private socket is refused rather than attached, and shutdown signals only the exact child PID, never `herdr server stop` or a process-name match. Generated config uses a profile-less non-login shell, disables remote update/manifest checks, and sets `resume_agents_on_restore=false` because Golem owns resurrection. No `[herdr]` remains tmux; owned-server startup/protocol failure loudly falls back to tmux. Backend policy still makes unsupported combinations explicit (herdr: `400` for non-pi, `501` attach/steer). Herdr states remain observations, never settlements, and protocol-20's untimestamped non-resumable events retain receipt-time `as_of` plus polling. A hard golemd crash can leave its namespaced child alive; the next golemd refuses to adopt or kill it, requiring operator/service-manager cleanup rather than risking an unrelated process.
24. **Tiamat model inventory is dynamic but harness availability remains operator-owned.** Presence of `[tiamat]` augments only an explicitly configured Pi harness by fetching `/tiamat/v1/models` through the existing Router URL and token-file conventions. One bounded, concurrency-collapsed resolver supplies both capability advertisement and dispatch authorization, maps only Pi-supported Anthropic Messages/OpenAI Completions/Responses wires, excludes unavailable records, retains degraded records, applies optional provider/exact-model restrictions, sorts output, and caps response bytes and model count. Fresh results have a short TTL; refresh failure may return an explicitly stale snapshot only for the configured stale interval. Dynamic outage never removes or blocks static Pi or other harness capabilities: with no usable catalogue the status is `unavailable` and only unverifiable dynamic selections fail closed. Acceptance durably pins the selected credential-free row, and Start/Resume provision from that exact row rather than independently rediscovering; later Router removal may still make inference fail, but cannot change worker construction. Workers use unscoped API paths plus a validated raw `x-tiamat-provider` header, including for provider IDs containing `/`. Generated provider namespaces are reserved from static config. Router token contents remain out of config, protocol, store, logs, and artifacts; workers receive only the existing token-file path and resolve it at inference time.
